# BLOCKING CONSTRAINTS — Read Before Anything Else

> These are not suggestions. Each constraint below was discovered through failure.
> Acknowledge each one explicitly before proceeding.

- [ ] CONSTRAINT: **Windows SSL proxy** — antivirus intercepts HTTPS; `git push` requires `http.sslVerify=false` (already set locally). yt-dlp must use `--no-check-certificate`. Do NOT add any library that makes raw HTTPS calls without this bypass.
- [ ] CONSTRAINT: **Windows cp1252 encoding** — yt-dlp subprocess must be launched with `PYTHONUTF8=1` in env or accented characters (é, í, ú) become `�`, breaking title matching.
- [ ] CONSTRAINT: **W-06 is a false positive — do NOT remove the redundant `row_status_changed.emit(METADATA_READY)` in `_metadata_worker`**. The emit IS load-bearing because `_refresh_start_button` (one of three slots on `row_status_changed`) only sees the transition via the signal — `update_row_metadata.update_row_status` is a direct method call, not a signal emit. Removing it leaves the Start button permanently disabled after metadata fetch. Documented in REVIEW.md.

**Do not proceed until all boxes are checked.**

## Critical Anti-Patterns

| Pattern | Description | Severity | Prevention Mechanism |
|---------|-------------|----------|---------------------|
| ytmsearch: prefix | `ytmsearch:` is NOT a valid yt-dlp URL scheme (fails with "Unsupported url scheme"). | blocking | Hard-coded `music.youtube.com/search?q=` in `_search_yt_candidates` |
| spotDL / ytmusicapi | Both fail with SSL CERTIFICATE_VERIFY_FAILED on this machine (antivirus proxy). | blocking | Not in requirements.txt |
| Subprocess cp1252 encoding | yt-dlp without `PYTHONUTF8=1` corrupts accented chars on Windows. | blocking | Env var set in `_search_yt_candidates` |
| Monkey-patching Qt event handlers | `self._table.keyPressEvent = self._handle_key` is fragile — PySide6 may bypass Python attribute lookup. | advisory | Replaced with `_DeleteAwareTableWidget` subclass (W-11). Subclass any Qt event handler you need to override. |
| Removing emit because "internal call does the same" | A direct method call does NOT trigger signal slots. Check ALL listeners of a signal before removing an emit. | blocking | Document the listener-tree of each `Signal.connect` site. |
| `unlink(missing_ok=True)` + `shutil.move` | Destroys user data on partial failure. | blocking | Use `os.replace(tmp, dest)` atomic rename pattern (C-04). |

The codebase review uncovered a systemic pattern: worker-thread / main-thread Qt boundary handling was loose, with several "what if event X falls in window Y between emits A and B" race conditions (C-03, C-04, C-05, C-07, C-11). All now fixed with bounded waits, atomic operations, and proper process-tree teardown.

W-06 is the interesting failure case — the reviewer's "remove redundant emit" suggestion looked correct on the surface but missed that `_refresh_start_button` only listens on the signal, not on the direct method call inside `update_row_metadata`. Caught by reasoning about the listener tree, not by tests. Take this as a lesson: before removing any `signal.emit()`, enumerate ALL listeners of that signal and verify each can still observe the state transition through some other path.

The 21 fix commits are atomic — each can be reverted individually with `git revert <sha>` if a regression surfaces. The CODEBASE-REVIEW-2026-05-19.md report includes file:line citations for every finding.
