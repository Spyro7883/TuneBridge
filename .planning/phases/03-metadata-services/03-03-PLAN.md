    ```python
    # ---------------------------------------------------------------------------
    # Metadata routing — single entry point for worker threads
    # ---------------------------------------------------------------------------


    def fetch_metadata_for_row(
        url:            str,
        url_type:       str,
        spotify_client: "SpotifyClient | None",
        yt_extractor:   "YoutubeExtractor",
    ) -> dict:
        """Route a row to the correct metadata service and tag with `source`.

        Spotify URLs: parse track/album resource type + ID via regex; call
        SpotifyClient.get_track_metadata or get_album_metadata accordingly.
        YouTube URLs: delegate to YoutubeExtractor.extract_metadata.

        Returns the service's metadata dict with an added `source` key
        ("Spotify" or "YouTube") per D-05.
        """
        if url_type == "Spotify":
            match = _SPOTIFY_RESOURCE_RE.search(url)
            if match:
                resource_type = match.group(1)   # "track" or "album"
                resource_id   = match.group(2)
            else:
                # Fallback for non-canonical Spotify URLs — assume track.
                resource_type = "track"
                resource_id   = url.split("/")[-1].split("?")[0]

            if resource_type == "album":
                metadata = spotify_client.get_album_metadata(resource_id)
            else:
                metadata = spotify_client.get_track_metadata(resource_id)
            metadata["source"] = "Spotify"
            return metadata

        # YouTube path
        metadata = yt_extractor.extract_metadata(url)
        metadata["source"] = "YouTube"
        return metadata
    ```

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| URL string → regex extraction | Pre-classified URL string (Phase 2 validated) → `_SPOTIFY_RESOURCE_RE` capture |
| Captured ID → Spotify API path | `match.group(2)` interpolated into `https://api.spotify.com/v1/tracks/{id}` URL |
| Worker thread → Qt main thread | `_Dispatcher.metadata_ready.emit(row_id, dict)` carries dict across thread boundary |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-11 | T (Tampering) | Malicious Spotify-like URL containing path traversal characters | mitigate | `_SPOTIFY_RESOURCE_RE` constrains capture group 2 to `[A-Za-z0-9]+` — no `.`, `/`, `?` can survive the regex; non-matching URLs fall back to a final-segment split that still strips query params |
| T-03-12 | T (Tampering) | url_type string spoofed to bypass Spotify routing | accept | `url_type` originates from `classify_url()` (Phase 2 trusted source); only "Spotify" or "YouTube" produce metadata calls. Any other value is treated as YouTube via else-branch — failure surfaces as YoutubeExtractor exception → "Failed — metadata" (Plan 04) |
| T-03-13 | I (Information disclosure) | Metadata dict passed via Signal leaks into other QObjects | accept | Signal connection is explicit (`metadata_ready.connect(table.update_row_metadata)`) — only the BatchTable slot receives the dict; no broadcast |
| T-03-14 | D (Denial of service) | Signal queue backlog when many rows complete at once | accept | Qt queued connection is bounded by event loop — main thread processes one slot at a time. Backlog manifests as UI lag, not crash |
</threat_model>
