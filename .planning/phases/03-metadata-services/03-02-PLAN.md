    ```python
    class YoutubeExtractor:
        """Extract title + channel via yt-dlp info extraction (META-02).

        Parses the video title into `(guessed)`-labeled artist + track_title
        fields per META-03 / D-06 / D-08 / D-09. Channel name is captured but
        NEVER used as an artist guess (D-09).
        """

        _YDL_OPTS: dict = {
            "quiet":        True,
            "no_warnings":  True,
            "extract_flat": False,
            "noplaylist":   True,
        }

        def extract_metadata(self, url: str) -> dict:
            with yt_dlp.YoutubeDL(self._YDL_OPTS) as ydl:
                info = ydl.extract_info(url, download=False)

            raw_title = info.get("title", "")
            channel   = info.get("channel") or info.get("uploader", "")

            result: dict = {
                "title":   raw_title,
                "channel": channel,
            }

            # D-08: split on FIRST occurrence of " - " only. D-09: no separator -> no artist.
            if " - " in raw_title:
                artist_part, track_part = raw_title.split(" - ", 1)
                result["artist"]      = f"{artist_part} (guessed)"
                result["track_title"] = f"{track_part} (guessed)"
            else:
                # D-09: channel name is NOT used as artist guess.
                result["track_title"] = f"{raw_title} (guessed)"

            return result
    ```

    CRITICAL constraints enforced:
    - `yt_dlp` is the module-level name (Plan 01 added `import yt_dlp`) — do NOT use `from yt_dlp import YoutubeDL` (would break `patch("tunebridge.yt_dlp.YoutubeDL")`)

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| User input → yt-dlp | URL string passed from `_process_urls` reaches `yt_dlp.YoutubeDL.extract_info` |
| yt-dlp → app memory | Info dict (title, channel, uploader, etc.) returned from yt-dlp into app process |
| Untrusted title text → table cell | Raw video titles (attacker-controlled in principle) are stored verbatim then formatted with " (guessed)" |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-06 | T (Tampering) | Attacker-controlled URL passed to yt-dlp | mitigate | `classify_url()` (Phase 2) pre-validates URL against `_YOUTUBE_RE` regex before extractor is invoked; non-YouTube URLs never reach this path |
| T-03-07 | I (Information disclosure) | Verbose yt-dlp output leaks viewer history / cookies | mitigate | `_YDL_OPTS` sets `quiet=True` and `no_warnings=True` — no stdout/stderr leakage |
| T-03-08 | T (Tampering) | Malicious title string injected via " - " separator manipulates artist field | accept | Low risk — artist/title are display-only strings in Phase 3; downstream consumers (Plan 04 row display, Phase 4 download) operate on the labeled "(guessed)" strings which clearly signal untrusted provenance |
| T-03-09 | D (Denial of service) | Slow yt-dlp extraction blocks worker thread | accept | Phase 3 scope per CONTEXT.md "Claude's Discretion" — single attempt; failure surfaces as `Failed — metadata` per D-07 (owned by Plan 04) |
| T-03-10 | E (Elevation of privilege) | yt-dlp downloads malicious file to disk | mitigate | `download=False` keyword on `extract_info` — info extraction only, no file write (Pitfall 4) |
</threat_model>
