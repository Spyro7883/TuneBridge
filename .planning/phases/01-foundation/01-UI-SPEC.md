## Spacing Scale

Declared values (multiples of 4):

| Token | px value | tkinter usage |
|-------|----------|---------------|
| xs | 4 | Icon gaps, tight inline padding |
| sm | 8 | Compact widget padding |
| md | 16 | Default padx/pady on most widgets |
| lg | 20 | Outer horizontal padx (window edges) |
| xl | 24 | Section vertical spacing |
| 2xl | 32 | — (reserved for future phases) |
| 3xl | 48 | — (reserved for future phases) |

Exceptions:
- Title top padding: `pady=(16, 4)` — 16px top, 4px bottom (from RESEARCH.md Pattern 6)
- Input placeholder frame height: 60px fixed — maintains layout slot for Phase 2 (from RESEARCH.md Pattern 6)
- Status bar bottom margin: `pady=(0, 10)` — 10px (from RESEARCH.md Pattern 6)
- Treeview row height: 28px — prevents Segoe UI descender clipping (from RESEARCH.md Pitfall 4)

## Typography

| Role | Size | Weight | Line Height | tkinter style |
|------|------|--------|-------------|---------------|
| Body | 10pt | regular (400) | 1.4 (row height 28px enforces this) | `("Segoe UI", 10)` — TLabel, Treeview cells |
| Label / secondary | 9pt | regular (400) | 1.4 | `("Segoe UI", 9)` — Dim.TLabel, Treeview.Heading |
| Heading / display | 18pt | bold (700) | 1.2 | `("Segoe UI", 18, "bold")` — Title.TLabel |

**Notes:**
- 3 sizes declared; 2 weights (regular, bold). No italic.
- Treeview headings use 9pt bold — same bold weight as heading, smaller size for column labels.
- Unicode characters `✓` (U+2713) and `✗` (U+2717) render correctly in Treeview cells on Tk 8.6 / Windows 10. Do not render these to stdout without UTF-8 wrapper.

## Interaction Contract

### Status state machine (PROC-02)

States cycle in fixed order. No backward transitions.

```
Queued → Fetching metadata → Downloading → Retuning → Awaiting folder → Saving → Uploading → Done ✓
                                                                                              Failed ✗
```

- `SongStatus(str, Enum)` — values are display strings, usable directly in `tree.set()`
- Terminal states: `Done ✓` and `Failed ✗` — no further transitions
- Each state transition is a call to `BatchTable.update_row_status(row_id, status)`
- All calls to `update_row_status` must come from the main thread via `self.after(0, ...)`

### Thread safety contract

- Worker threads: NEVER call tkinter methods directly
- All GUI mutations scheduled via `root.after(0, callback, *args)`
- Workers started from button handler only (not from `__init__`) — mainloop must be running first
- Thread count: `min(len(urls), 4)` — recalculated per batch, not hardcoded

### Mock worker behavior (Phase 1 demo)

Status progression with simulated delays:

| Status | Delay before next |
|--------|------------------|
| Queued | 0.0s |
| Fetching metadata | 0.3s |
| Downloading | 0.8s |
| Retuning | 0.6s |
| Awaiting folder | 0.2s |
| Saving | 0.2s |
| Uploading | 0.4s |
| Done ✓ | — (terminal) |

Failed path: any worker exception → `self.after(0, update_row_status, row_id, SongStatus.FAILED)`

### Input placeholder frame

- Fixed height 60px with `pack_propagate(False)`
- Phase 1: contains "Start Demo" button (for pipeline demo)
- Phase 2 will replace/populate this frame with URL paste area — frame must remain intact

### Status bar

- Default text: `"Ready — add songs to begin"`
- During batch: `"Processing N/M..."` (thread-safe via `self.after(0, self._status_var.set, ...)`)
- After batch: `"Done — N tracks processed"` or `"Done — N succeeded, M failed"`

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | `"Start Demo"` |
| Window title | `"TuneBridge"` |
| App heading | `"TuneBridge"` |
| Status bar default | `"Ready — add songs to begin"` |
| Status bar during batch | `"Processing {done}/{total}..."` |
| Status bar after batch (success) | `"Done — {N} tracks processed"` |
| Status bar after batch (mixed) | `"Done — {N} succeeded, {M} failed"` |
| Type badge — Spotify | `"[Spotify]"` (placeholder, not yet populated in Phase 1) |
| Type badge — YouTube | `"[YouTube]"` (placeholder, not yet populated in Phase 1) |
| Status: terminal success | `"Done ✓"` |
| Status: terminal failure | `"Failed ✗"` |
| Empty table state | No separate empty state widget — table simply shows no rows; status bar shows default copy |

**Destructive actions in Phase 1:** None. No delete, cancel, or irreversible action in this phase scope.

**Error states in Phase 1:** A worker exception sets that row to `Failed ✗`. No modal dialog in Phase 1 — error is visible in the row status column only.

## Public API Contract (for Phase 2+ integration)

These method signatures are part of the design contract. Phase 2+ must be able to call them without modification to Phase 1 code.

| Method | Signature | Called by |
|--------|-----------|-----------|
| `BatchTable.add_row` | `(url: str, title: str = "", url_type: str = "") -> str` | Phase 2 after URL detection |
| `BatchTable.update_row_status` | `(row_id: str, status: str) -> None` | Phase 3+ workers via `after()` |
| `BatchTable.update_row_title` | `(row_id: str, title: str) -> None` | Phase 3 after metadata fetch |
| `BatchTable.update_row_type` | `(row_id: str, url_type: str) -> None` | Phase 2 after URL type detection |
| `BatchTable.clear` | `() -> None` | New batch start |
